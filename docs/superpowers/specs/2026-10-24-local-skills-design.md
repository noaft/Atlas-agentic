# Local skills and shared-folder interoperability

User correction: skills must be flexible local folders, created by Atlas or users, and imported from local sources rather than requiring GitHub. Follow the shared .agents/skills conventions documented by vercel-labs/skills. One skill = <name>/SKILL.md plus optional resources.

Keep project storage at <validated starting project>/.agents/skills. Default Personal creation/discovery uses Universal's $XDG_CONFIG_HOME/agents/skills (fallback ~/.config/agents/skills on all platforms, matching that CLI). Also discover ~/.agents/skills, the canonical global copy used by skills CLI 1.7.4, then existing Atlas config skills as ordered fallbacks, without deleting/moving originals. Explicit ATLAS_CONFIG_DIR continues to isolate all Atlas skill roots. Duplicate Personal names prefer the primary shared root; operations on an existing fallback skill address its actual root. New local skills need no remote source metadata.

Atlas consumes standard folders installed by any tool. Document npx skills add <source> --agent universal --copy for project and --global for Personal; that installer handles local paths, GitLab, arbitrary Git URLs and other supported sources. Atlas need not duplicate all those installers or execute npx implicitly. In-app Create and Import local are primary; existing GitHub import remains optional under additional sources.

Add local skill creation with name/title/summary/instructions and optional UTF-8 supporting files. Add read/edit for existing skill documents, preserving resources and enabled state; reject name changes and detect conflicting edits with a fingerprint bound to package bytes and the selected storage root. Editing an imported skill makes a local fork (clear remote provenance). Local folder or SKILL.md import previews text and relative files, then revalidates a whole-package fingerprint before install. Files imported individually import only that file; folders preserve their resources. No scripts run. Existing bounds, leases, staging recovery and validation apply.

Add create_skill runtime tool even when no skills exist. Project writes use ModifyWorkspace authorization; Personal writes require an outside-workspace modification approval in Ask and Workspace. Creation never overwrites, runs scripts, or saves skills unprompted. Newly saved skills are discovered on subsequent requests; the creator receives its ID immediately. Existing load_skill snapshots retain their stable instructions for running requests.

UI preserves creation/import/edit drafts across category switches and Back; captures context per request; rejects stale project/scope/preview results. Native file/folder dialogs use existing permission through atlas-api.ts. All filesystem work remains in Rust workers; no frontend permission expansion or GitHub credentials.
