# Skills catalog and installation design

Approved direction from the conversation: preload short descriptions, load instructions/resources only when selected, leave ratings for later. The user authorized implementation and explicitly requests installation first in the Skills UI, with installed skills in a separate section. This supersedes the search-first and installed-first portions of the earlier Settings/MCP proposal; MCP redesign remains a separate pending workstream.

## Behavior

Keep standard Personal/Project skill folders as authoritative storage and the existing immutable per-request catalog. Do not add a database or duplicate package store. Preload ID/name/title/description, never full instructions. Encourage concise when-to-use descriptions (roughly 30 tokens, no exact provider-independent tokenizer claim). Expand the bounded enabled catalog from 64 to 128 to cover 100 skills, retain 64 KiB metadata and 32 MiB snapshots, and report omission warnings.

Expose preview_skill(url) and install_skill(token, scope) through existing runtime tools. Public GitHub acquisition reuses existing validated pinned downloads. Preview downloads immutable packages as data, returns full instructions, relative file names and a request-local random token. Limit the batch to 8 candidates, 8 MiB package bytes and 64 KiB serialized preview output; larger sources request a narrower folder URL. No directories are created by preview. Installation accepts only a retained preview token, never arbitrary remote source data; publishes those exact bytes through SkillStore.install without overwrite or script execution. A successful new preview replaces old tokens; tokens cannot be forged or reused to overwrite. The import tools remain available with an empty installed catalog. Preview uses ExternalTool approval; Project installation uses ModifyWorkspace and Personal uses ModifyOutsideWorkspace. New installations become available next request. Credentials and development environment files are never used for downloads.

Skills Settings remains a dedicated category. Put an open Add skills section at the top with a shared explicit destination selector and workspace hint, visible GitHub URL/preview and local file/folder actions. Put installed skills/search/counts in a distinct section below. Preserve reviewed previews, per-source installs/batch outcomes, cached documents/editors, focus, async generation and workspace ownership. Skills apply immediately, independently of model Save/Discard. No Create form and no ratings yet.

## Verification

Tests first for install-first hierarchy and usable imports, source-only preview, token/scope validation, exact package publication, denial without directories/network, duplicate installs, expired/forged tokens, output/package limits, empty-catalog registration and preloaded metadata without instructions. Existing skill/editor/ownership tests must remain green. Run Rust/desktop/Tauri formats, tests, lint and builds; disclose platform prerequisite failures.
