# Skills implementation plan

**Goal:** Implement the approved GitHub-link import and lazy skill loading design.
**Spec:** ../specs/2026-10-24-skills-design.md
**Architecture:** Rust skill catalog/store and read-only tool; bounded GitHub source importer; typed Tauri bridge; retained Skills Settings panel.
**Tech stack:** Rust, reqwest, YAML frontmatter, existing Tauri/TypeScript UI.

## Tasks
- [x] Core: test/discover/validate personal and project skills, scoped IDs, enabled state, resource loading, atomic install, and register load_skill through existing runtime tools.

- [x] UI: add Skills category, scope selection, installed list, View, enable/disable, source preview, Install and explicit Update; retain panel/drafts and reject stale async results.

## Shared contract
SkillScope = personal | project. SkillSource = {repository, reference, revision, path}, repository owner/repo, revision full SHA, path relative folder. SkillInfo = {id,name,title,description,scope,enabled,source?}. SkillCatalog = {skills,issues}. SkillDocument = {skill,content,files}. SkillPreview = {source,name,title,description,content,files}. IDs are scope:name. Preview supplies immutable source; install revalidates/reloads it. Whole-package files are a BTreeMap<String,Vec<u8>>.

Review malformed/oversized metadata, path traversal/symlinks, duplicate names and immutable updates, saved workspace conflicts, stale async UI and loader resource reads outside registered skill roots. Preserve unrelated changes and never include credentials.
